3. Các sản phẩm phần mềm bắt buộc

  • Frontend: giao diện Web và phần Desktop theo phạm vi nhóm thống nhất.
  • Backend/API: API phục vụ nghiệp vụ và kết nối frontend/database.
  • Database: ERD, schema, migration/seed, data dictionary.
  • Authentication: đăng nhập, đăng xuất, bảo vệ API.
  • Authorization/RBAC: quyền theo vai trò.
  • CRUD: thêm/sửa/xóa/xem + validation.
  • Search/Filter: tìm kiếm và lọc dữ liệu.
  • Dashboard: thống kê tổng quan.
  • Reports: tối thiểu 2 báo cáo; hỗ trợ PDF/Excel theo phạm vi đề tài.
  • External integration: ít nhất 1 dịch vụ bên ngoài.
  • Testing: unit/integration/system/UAT + regression; ≥35 test case.
  • Deployment: deploy demo hoặc cloud, có hướng dẫn chạy.

4. Khái niệm và nhiệm vụ từng vai trò

👑 Hoàng — PM/Scrum Master + Integration

Quản lý dự án · Điều phối · Tích hợp

Khái niệm: PM chịu trách nhiệm lập kế hoạch, điều phối nguồn lực, theo dõi phạm vi–thời gian–chi phí–chất lượng–rủi ro. Scrum Master hỗ trợ nhóm làm việc đúng quy trình. Integration chịu trách nhiệm ghép các phần Frontend, Backend, Database thành một hệ thống chạy end-to-end.

Công việc chính:

  • Project Charter, PMP, mục tiêu SMART.
  • Scope, WBS, WBS Dictionary, Gantt và baseline.
  • Phân công RACI, workload, timesheet.
  • Theo dõi planned vs actual mỗi tuần.
  • Quản lý risk register, issue log, change log.
  • Điều phối họp, biên bản, status report.
  • Quản lý Git workflow/milestone và phối hợp merge.
  • Tích hợp frontend + backend + database + deploy.
  • Release checklist, demo rehearsal, đóng dự án, lessons learned.

Thời gian trọng tâm: Tuần 1–8; tích hợp mạnh từ Tuần 3–7.

📋 Ba — BA/PO

Phân tích nghiệp vụ · Quản lý yêu cầu

Khái niệm: BA (Business Analyst) phân tích vấn đề, người dùng và quy trình nghiệp vụ; PO (Product Owner) xác định giá trị sản phẩm, ưu tiên backlog và xác nhận chức năng đáp ứng nhu cầu.

Công việc chính:

  • Xác định stakeholder và actor.
  • Khảo sát nghiệp vụ dịch vụ sự kiện.
  • Viết problem statement và mục tiêu SMART.
  • Xây dựng SRS, User Story/Use Case.
  • Viết Acceptance Criteria.
  • Chia In-scope / Out-of-scope.
  • Ưu tiên backlog Must-have / Should-have / Could-have.
  • WBS phần nghiệp vụ và Requirement Traceability Matrix.
  • Phối hợp QA để đảm bảo yêu cầu truy vết được tới test case.
  • Nghiệm thu nghiệp vụ/UAT.

Thời gian trọng tâm: Tuần 1–2 là cao nhất; tiếp tục hỗ trợ xuyên suốt Tuần 3–8.

🎨 Nhân — UI/UX + Frontend

Thiết kế trải nghiệm · Xây dựng giao diện

Khái niệm: UI/UX thiết kế cách người dùng tương tác với hệ thống; Frontend hiện thực thiết kế thành giao diện thật và kết nối với API.

Công việc chính:

  • User flow và information architecture.
  • Wireframe → prototype → UI final.
  • Design system: màu, font, button, form, table, modal, trạng thái.
  • Thiết kế dashboard và các màn hình CRUD.
  • Responsive và usability.
  • Validation/error/loading/empty state.
  • Gọi API và xử lý dữ liệu frontend.
  • Quản lý state và route/navigation.
  • Đóng góp source Git và sửa lỗi UI.

Thời gian trọng tâm: Tuần 2–7; Tuần 8 tập trung hoàn thiện UX và fix lỗi.

⚙️ Phúc — Backend/API + DevOps

Nghiệp vụ server · API · Triển khai

Khái niệm: Backend xử lý business logic, validation, authentication/authorization và cung cấp API. DevOps đảm bảo môi trường chạy, version control, CI/CD và deployment.

Công việc chính:

  • Thiết kế kiến trúc backend.
  • API contract/spec.
  • Authentication + JWT/session theo công nghệ chọn.
  • RBAC và authorization.
  • CRUD + business logic + validation.
  • Error handling và security cơ bản.
  • Search/filter, dashboard/report API.
  • Tích hợp dịch vụ ngoài.
  • Docker/environment/config nếu phù hợp.
  • CI/CD hoặc deploy cloud.
  • README/deployment guide.

Thời gian trọng tâm: Tuần 2–8; deploy mạnh ở Tuần 7.

🗄️ Hậu — Database + QA/Tester

Dữ liệu · Kiểm thử · Chất lượng

Khái niệm: Database chịu trách nhiệm thiết kế và bảo đảm tính toàn vẹn dữ liệu. QA/Tester lập chiến lược kiểm thử, tạo test case, phát hiện defect và xác nhận hệ thống đạt tiêu chí chất lượng.

Công việc chính:

  • ERD, schema và data dictionary.
  • Thiết kế 8–12 bảng theo yêu cầu mức Khá.
  • Khóa chính/ngoại, constraint, index và quan hệ.
  • Migration/seed dữ liệu mẫu.
  • Query phục vụ nghiệp vụ, dashboard và báo cáo.
  • Test plan, test strategy, Definition of Done.
  • Tối thiểu ≥35 test case.
  • Unit/integration/system/UAT/regression phối hợp cùng team.
  • Defect log, severity/priority, owner, retest.
  • Traceability giữa requirement → test case → kết quả.

Thời gian trọng tâm: Database Tuần 2–4; QA xuyên suốt Tuần 3–8, cao điểm Tuần 6–7.

10. GitHub & minh chứng cá nhân

  • Repository có README, hướng dẫn cài đặt/chạy, cấu trúc branch, issue/milestone.
  • Mỗi thành viên phải có commit và ticket/issue phản ánh đúng phần việc.
  • Không để một người làm toàn bộ source rồi các thành viên chỉ đứng tên.
  • Thống nhất branch: main → develop → feature branches.
  • Pull Request nên có review trước khi merge vào develop/main.
  • Folder /docs chứa toàn bộ hồ sơ quản lý dự án.
  • Mỗi người duy trì timesheet và danh sách đầu việc cá nhân.

12. Điều kiện nghiệm thu cuối kỳ

  • Đề tài và phạm vi đã được GV duyệt.
  • Sản phẩm chạy end-to-end.
  • ≥80% phạm vi baseline.
  • 100% chức năng Must-have hoàn thành.
  • Đủ hồ sơ quản lý dự án.
  • Test pass ≥90% và test ưu tiên cao đạt.
  • Không còn lỗi Critical/High chưa xử lý.
  • Repository có đóng góp của cả 5 thành viên.
  • Mỗi thành viên giải thích được phần mình phụ trách khi vấn đáp.
  • Có demo, dữ liệu mẫu và tài khoản theo vai trò.

Sản phẩm nộp cuối kỳ

  • Repository + source code.
  • Ứng dụng chạy/deploy + tài khoản demo.
  • SRS + scope + use case/user story + acceptance + RTM.
  • Architecture + ERD + data dictionary + API spec + deployment diagram.
  • PMP + Gantt + cost + RACI/timesheet + communication + risk + procurement + quality + change + closure.
  • Test plan + ≥35 test case + test report + defect log + UAT/regression evidence.
  • Báo cáo cuối kỳ.
  • Slide 12–18 trang.
  • Video demo 5–8 phút.
  • Minh chứng cá nhân: task + commit + ticket + timesheet + tự đánh giá/đánh giá chéo.

  4. Tuần 5: hoàn thiện nghiệp vụ, dashboard, report và integration.
  5. Tuần 6: feature complete; bắt đầu sửa lỗi nghiêm túc.
  6. Tuần 7: UAT + regression + deploy + tài liệu + video.
  7. Tuần 8: chỉ chốt release, hồ sơ, slide và luyện vấn đáp; không bắt đầu chức năng lớn mới.
  8. AI dự báo chi phí: chỉ thực hiện nếu MVP đã ổn định. Nếu không đủ thời gian, bỏ AI để bảo vệ chất lượng MVP.
